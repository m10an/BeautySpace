## Подтверждённые дефекты

### QA-01 — недостаточный контраст текста, высокий приоритет

На четырёх разрешениях axe обнаруживает нарушения `color-contrast`. Для mobile-390 нарушены 8 из 9 проверенных экранов; на `prompts` в этом состоянии автоматических нарушений не найдено. Это не подтверждает полное соответствие этого экрана WCAG.

Примеры из axe:

| Селектор / пример | Фактический контраст | Требование для этого мелкого текста |
| --- | ---: | ---: |
| `.weekdays > span:nth-child(1)` и другие дни недели | 2,82:1 | 4,5:1 |
| `#ritual > .panel:nth-child(1) > .eyebrow` и похожие заголовки | 3,02:1 | 4,5:1 |
| `.hair-body > .muted` | 4,28:1 | 4,5:1 |
| `.stat:nth-child(1) > span` | 4,40:1 | 4,5:1 |

Воспроизведение: `npm run test:audit -- --grep axe`. Полные селекторы, failureSummary и incomplete — во вложении `axe-results` отчёта и trace. Изменение цветов/типографики требует согласования; в этой ветке CSS не исправлялся.

### QA-02 — горизонтальное переполнение результата INCI, средний приоритет

1. Открыть Ingredient Check.
2. Ввести `Aqua, Parfum, ` и 12 повторений строки `VeryLongUnknownIngredient` без пробелов внутри последнего имени.
3. Нажать Analyze ingredients.

Непрерывный текст в `.inci-item-head strong` выходит за viewport; `document.documentElement.scrollWidth` превышает ширину документа. Воспроизводится на 320, 390, 768 и 1440 px. Других пересечений контролов и ошибок центрирования в проверенном сценарии не обнаружено.

Возможное направление исправления после согласования: перенос непрерывных слов и ограничение flex-элементов. Исправление не внесено, так как меняет интерфейс.

### QA-03 — Google font import игнорируется браузером, средний/низкий приоритет

В `style.css:40` `@import` Google GFS Didot стоит после обычных CSS-правил. По правилам CSS такой import игнорируется. Во всех четырёх browser-проектах проверено отсутствие этого import в CSSOM; font-family при этом продолжает упоминать GFS Didot и serif-fallbacks.

Это противоречит описанной в README V7 возможности загрузки Google шрифта онлайн. Serif fallback работает; отсутствие шрифта не ломает запуск приложения. Перемещение import или смена способа загрузки требует согласования и не выполнялось. Доступность Google Fonts из реальной сети и визуальный вид с этим шрифтом не проверялись.

## Особенности алгоритма и риски для уточнения

Это не принятые требования и не автоматически доказанные дефекты:

- Флагация основана на строках `category`/`note`, а не на числовых свойствах ингредиента. Изменение редакционного текста базы может изменить процент.
- Неизвестные исключены из знаменателя; дубликаты учитываются повторно; концентрация и порядок не влияют.
- Список молча ограничивается 200 элементами. Нужен критерий UX для длинных списков.
- До завершения fetch справочник равен пустому массиву, кнопка анализа активна; запрос может показать «0 recognized». После успешного fetch уже показанный результат автоматически не пересчитывается. Это выявлено анализом кода, отдельно не воспроизводилось в browser-тесте с задержкой.
- Поиска по продуктам нет, поэтому соответствующие E2E не выдумывались. Нет и медицинской формулы комедогенности: проверяется процент отмеченных совпадений.

## Что осталось непроверенным

- Соответствие внешнему ТЗ/макетам, утверждённым токенам и шрифтам: их нет в репозитории.
- Визуальная регрессия по утверждённым PNG: 4 явно skipped, автоматического принятия эталонов не было.
- Физические устройства, Google Chrome branded build, Safari/iOS/WebKit, Firefox, другие ОС и системные наборы шрифтов.
- Работа service worker/offline cache и обновлений PWA: в regression-контекстах SW заблокирован для детерминизма.
- Импорт/экспорт старых резервных копий, миграции всех исторических схем, storage quota, повреждённые данные и длительная эксплуатация.
- Полная WCAG-сертификация, клавиатура/screen reader, ручная оценка incomplete axe, все варианты масштаба текста и все состояния контента.
- Медицинская достоверность категорий и примечаний, источники данных, оригинальность текстов и права на изображения.
- Реальный запуск workflow на GitHub Actions и удалённый PR.

Вопросы для согласования перечислены в `docs/QA.md`. Исходники приложения, база, localStorage пользователя и бизнес-логика не изменены; merge/деплой не выполнялись.
