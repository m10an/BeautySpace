## Фактическая формула и данные

`ingredients-db.json` — массив из 107 объектов `{ "name": string, "category": string, "note": string }`. Полей `score`, `concentration`, `weight` нет. Нормализованные имена уникальны.

`ingredients.js` выполняет следующие операции:

1. Убирает `Ingredients:`/`Ingredients：` только в начале строки (начальные пробелы перед префиксом не удаляет).
2. Разбивает по запятым, `;` и переводам строки; удаляет начальную нумерацию `1.`/`1)`, пробелы и пустые элементы. Берёт первые 200 элементов; дубликаты не удаляет.
3. Для поиска переводит в нижний регистр, сжимает пробелы, удаляет точки и trim. Ищет точное совпадение, затем фиксированный алиас: water, vitamin e, shea butter, jojoba oil, argan oil, coconut oil, sunflower oil, perfume, fragrance.
4. Распознанная запись получает флаг, если `category` содержит `fragrance` или `allergen` без учёта регистра, либо `note` содержит `comedogenicity tests` или `comedogenicity lists`.
5. `signal = recognized > 0 ? Math.round(flags / recognized * 100) : 0`.
6. Ширина `.risk-fill` равна `signal%`. Подпись: 0 флагов — `No flagged matches`, 1–2 — `A few flagged matches`, 3+ — `Several flagged matches`.

Неизвестные ингредиенты не входят в знаменатель. Повторения входят и в числитель, и в знаменатель. Порядок и концентрация не учитываются. В реальной базе 12 записей соответствуют условию флага. Для `Aqua, Glycerin, Parfum, Missing Ingredient`: 4 ввода, 3 распознаны, 1 флаг, 33%. Для 1/8 — 13%; для 2/3 — 67%; при нуле распознанных — 0% без деления на ноль.

Это доля совпадений, отмеченных для дополнительного изучения, а не вероятность закупоривания пор. Запрошенные unit-тесты проверяют именно существующий алгоритм через неизменённый production closure в `node:vm`, с подменой только DOM/fetch. Числовые ожидания заданы литералами на независимых тестовых данных.

## Автоматизация

- `tests/unit/ingredients.test.cjs`: 24 сценария формулы, границ, ошибок, экранирования и схемы реальной базы.
- `tests/e2e/functional.spec.cjs`: INCI, пустые/неизвестные/HTML-запросы, алиасы, лимит 200, реальная база, сбой загрузки, диаграмма, localStorage и IndexedDB после reload.
- `tests/e2e/audit.spec.cjs`: четыре viewport, все девять экранов; переполнение документа/контролов, центрирование, семь колонок и пересечения контролов; axe включая color-contrast; serif fallback, текущие токены, стабильность повторного рендера и утверждённые screenshot baselines.
- Viewports: 320×740, 390×844 (touch/mobile Chromium), 768×1024 и 1440×900. Это эмуляция, не физические устройства и не Safari.
- Детерминизм: дата 2026-11-03, UTC/en-US, фиксированный random, fixture JSON, blocked service workers и внешние font-hosts, reduced motion. Отдельный E2E читает настоящую базу. Синтетическое фото генерируется из тестового PNG.
- Каждый тест получает отдельный browser context. Ни реальный профиль пользователя, ни его localStorage/IndexedDB не открываются.
- Фоновые и псевдоэлементы, полное покрытие всех вариантов данных и всех возможных пересечений геометрическими проверками не гарантируются.

## Локальный запуск

Требуется Node.js 24, npm и системные зависимости Playwright:

```bash
npm ci
npx playwright install --with-deps chromium
npm run test:unit
npm run test:e2e
npm run test:audit
npx playwright show-report
```

`test:e2e` — стабильный функциональный gate и computed styles. `test:audit` — диагностические проверки с известными дефектами; локально возвращает ненулевой код при нарушениях. `test:all` запускает все browser-тесты. CI сохраняет отдельные отчёты для regression и audit.

В этой среде браузеры установлены в `/workspace/pw-browsers`; локальные фактические прогоны использовали `PLAYWRIGHT_BROWSERS_PATH=/workspace/pw-browsers`. В GitHub Actions дополнительная переменная не нужна.

## Визуальные эталоны

В проекте нет утверждённых эталонов. Тест `@baseline` явно skipped для отсутствующих PNG. Повторный рендер проверяется отдельно и не заменяет сравнение с макетом. Скриншоты текущего интерфейса — материалы для ревью, не одобренные эталоны.

После согласования окружения, шрифтов и дизайна ревьюер может вручную создать **только отсутствующие** эталоны:

```bash
APPROVE_VISUAL_BASELINES=1 npm run test:visual -- --update-snapshots=missing
```

Нужно просмотреть каждый созданный PNG и diff, затем отдельно закоммитить одобренные изображения. При существующем визуальном отличии этот режим не обновляет PNG. В конфигурации `updateSnapshots: 'none'`; CI не задаёт переменную approval и не запускает обновление эталонов. Платформа и набор шрифтов должны совпадать с CI.

## CI

В существующий `.github/workflows/ci.yml` добавлены jobs `tests` и `audit`, сохранены push/pull_request и прежние статические проверки. `tests` блокирует ошибочные изменения; `audit` явно помечен `continue-on-error: true` на время исправления существующих UI-дефектов. Это не означает соответствие WCAG. После согласованных исправлений следует сделать audit блокирующим.

Playwright сохраняет HTML/JSON-отчёты, скриншоты, trace и video при ошибках. `upload-artifact` выполняется и после падения тестов; срок хранения 14 дней. В этой задаче удалённый workflow не запускался из-за 403 создания ветки.
